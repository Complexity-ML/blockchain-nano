# InventoryBridgeV2: offline Doppler proposal join

SOURCE ONLY. Neither this module nor its six new test groups have been executed. No SDK invocation, Node process, RPC, key, domain, signing, container or chain action was performed to prepare this package. Campaign04 and R are untouched. The two proposed new files belong alongside the existing `tools/doppler-launch` files; neither legacy `preview.mjs` nor `verify-review.mjs`, their schemas or their CLI change.

`verifyInventoryBridgeV2Proposal(input)` takes canonical JSON Buffers for a configuration, persisted review and externally proposed sidecar, plus an independently supplied SHA256 for each. It copies and validates all bytes before awaiting the existing verifier. The sidecar must bind the same configuration/review digests, SDK1.0.43, Base chain8453, predicted token, calldata hash, immutable two-domain/two-endpoint terms and explicit atomic lots. A digest computed from an untrusted file does not approve that file; the caller must obtain these three expected pins independently.

The existing offline `verifyUnsignedReview` will re-encode the SDK creation parameters when Root later runs this module. Its offline preview refuses attempted RPC. This proposal makes no new SDK calls or upstream APIs and preserves the pinned local SDK1.0.43 / viem2.33.3 dependencies. Existing successful or rejected simulation metadata cannot become a verified simulation here. Dependencies are recorded for source provenance, not a complete SDK/OS provider attestation.

The Solidity Terms tuple is explicit in `inventoryBridgeV2TermsComponents`: Base chain/domain/endpoint/ERC20, Native chain/domain/endpoint/nativeAsset, totalBaseSupply, baseLot, nativeLot, both directional verifier domains and maxProofBytes. Native currency is represented only by address(0); it is a different asset from the Base ERC20. Terms and route use the exact V2 type strings supplied by the separate Solidity source proposal. `termsHash` encodes the typehash followed by the static tuple; `routeId` encodes its typehash followed by the eight route fields. Nonzero distinct chain domains and verifier domains, nonzero endpoints/token, uint256 ranges and the prototype proof cap are checked. Equal numeric chain IDs or endpoint addresses on different domains do not merge those domains. The module proves neither endpoint code, verifier correctness nor domain finality.

Coverage is the **entire preissued Base supply**, never only the sale or circulating quantity. Supply must be an exact multiple of an explicit positive base lot; native coverage is `(totalBaseSupply/baseLot)*nativeLot`, checked against uint256. There is no implicit1:1 ratio, decimal adjustment, dust rounding or adopted economic choice. The synthetic tests use Base lot2 / Native lot7 and supply1000, giving3500 native atomic units. Annual minting other than the canonical zero setting is refused. The contract prototype must independently freeze/refuse an actual supply change; this tool cannot observe one.

Five disjoint declared allocations sum to total supply: auction sale, migration liquidity, vesting, treasury and unallocated. Auction sale equals the configuration's `numTokensToSell`. Unsold units remain a subset of auction sale, with maximum equal to that allocation and continued backing until authenticated settlement; they are not counted twice or automatically released. Vesting/treasury/LP categories are declarations about the remainder, **not SDK-encoded vesting, proven owners or executed distributions**. The legacy adapter does not encode a vesting schedule. This separation prevents excluded preallocations from reducing the declared coverage while making no unsupported allocation claim.

The result verifies only the proposal/encoding join. `nativeAssetRelationshipVerified`, `finalityVerified`, `activationVerified`, `simulationVerified`, `reserveAccountingVerified`, `endpointCodeVerified`, `supplyOnchainVerified`, `allocationExecutionVerified`, `economicTermsAdopted`, `signed`, `broadcast`, `productionReady` and `productionQualified` all remain false. A proposed native inventory amount is not a deposited reserve, a redemption guarantee, an activation permit, liquidity, USDC backing or a route to withdraw Doppler proceeds.

The six prepared test groups cover a non1:1 whole-supply join, corrupted/missing external pins and ambiguous JSON, all preissued categories/unsold accounting, dust/overflow/inflation, self-consistent sidecar disagreements with the actual SDK review, and caller mutation across the SDK await. Tests use only synthetic in-memory proposal/config/review bytes and the existing synthetic config fixture; a fetch sentinel refuses network in the success path. Their source is not a test result. Root may later stage the two additions in the unchanged existing package and qualify these specific groups in Docker; no automatic launch or on-chain action is included.
