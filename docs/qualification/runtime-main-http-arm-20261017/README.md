# Runtime ARM et vrai Nano/HTTP — preuves séparées, échecs conservés

Le candidat de sources `c6cdf780c68eab8b06306d76257bda9028928ea3` a produit huit assemblages ARM et neuf contrôles d’arité/aide vérifiés par un audit Root distinct. Le vrai Nano a aussi servi douze requêtes HTTP sur une DB genesis synthétique, avec deux démarrages/arrêts joints ; une preuve extraite de ces mêmes réponses a ensuite été vérifiée hors ligne. **La continuation hôte et le contrôle HTTP initialement concernés restent tous deux FAILED**. Ce dossier documentaire n’importe aucun des fichiers C++ de la branche candidate dans main, n’émet aucune admission et ne retargete aucun index de 24 logiciels.

## Assemblages et refus hôte

Le [lot Q02 antérieur](evidence/history/runtime-q02/result-public.json) a terminé cinq assemblages puis refusé `CXX-depositAudit` ; il n’avait lancé aucun CLI. La [continuation](evidence/runtime-continuation/result-public.json) a réalisé seulement trois M/CXX/MD/liens/ldd — depositAudit, slashingFixture, lifecycleSubmit — et trois arités. Les cinq autres exécutables ont été montés RO et soumis à six arités/aide dans ce même conteneur. Les neuf oracles ont réussi, ainsi que les comparaisons M/MD, les observations guest, l’identité d’image et le cleanup.

Le [fence hôte](evidence/runtime-continuation/host-fence-public.json) a pourtant refusé : le manifeste documentaire source a changé après son admission, de `4a3cbb61… / 2891` à `065fe6aa… / 2783`. Les champs différents sont SHA, taille, mtime et ctime. Cette mutation connue ne doit être ni annulée, ni rafraîchie, ni effacée de l’histoire ; le résultat hôte demeure `passed:false` et `retainedCoreHostAuthorityVerified:false`.

L’[audit Root séparé en lecture seule](evidence/runtime-cohort-audit/result-public.json) a vérifié les 1 256 autres inputs originaux et 33 produits par leurs autorités FD9/SHA, puis lu 537 argv opératoires : ce manifeste n’était pas une entrée du compilateur, du lien, du chargeur ou des CLI. Il atteste huit assemblages et neuf CLI, sans recompiler ni rejouer une commande. Il exclut ce seul manifeste de **cet audit circonscrit**, conserve `wholeHostQualificationPassed:false` et `failedEnvelopePreserved:true`. Les documents d’observations finales n’avaient pas un pin terminal indépendant antérieur : leurs pins ont été capturés par Root à la préparation ou à l’audit ; les cinq pins d’exécutables comparés avaient été capturés avant préparation. Aucune qualification globale d’autorités historiques n’en est déduite. [ASSESSMENT.json](ASSESSMENT.json) expose cette séparation et les huit pins publics ; ce fichier est documentaire, pas une admission.

## Vrai chemin main → serve → HTTP

Le [premier essai de préparation](evidence/smoke-01/preparation-failure-public.json) a refusé l’admission de nouveaux fichiers avant Docker, Node ou RPC ; le chemin/champ exact et l’acteur causal n’y étaient pas enregistrés. Il reste FAILED, sans attribution rétroactive.

Le [smoke suivant](evidence/smoke-02/result-public.json) a utilisé le Nano `011d646a… / 13467208`, le Core ARM `11c1494f… / 41225178` déjà retenu et l’image existante épinglée. Deux conteneurs avec Nano PID1, réseau none, aucun port publié ni P2P, ont ouvert la même DB entièrement synthétique : chainId 31337, profil Shanghai, hauteur zéro. L’allocation publique contient une adresse arbitraire avec balance 7, nonce 2, bytecode et slot 0 valant 42 ; aucune clé ou transaction n’est requise.

Les [douze réponses réelles](evidence/smoke-02/rpc-cases-public.json) comprennent l’identité et le header, balance/code/nonce/storage via le sélecteur hash canonique, getProof pour les clés `[0,1,0]`, les refus précis `-32602` et `-32005`, puis le même header et la même balance après réouverture. Les [deux TERM joints](evidence/smoke-02/stop-results-public.json) ont réellement donné exit0, sans OOM ni kill forcé ; cleanup et [fence des 1 239 inputs](evidence/smoke-02/input-fence-public.json) sont vrais. Il s’agit d’une réouverture de genesis, pas d’un crash ni d’un historique de blocs.

Ce contrôle reste néanmoins FAILED : la phase Node de vérification indépendante a rencontré [MODULE_NOT_FOUND pour ethers](evidence/smoke-02/independent-proof.stderr.log). Une [continuation hors ligne distincte](evidence/offline-proof-continuation/result-public.json), avec le NODE_PATH d’origine, a vérifié le [même vecteur HTTP](evidence/smoke-02/proof-vector.json), SHA `b48e33ae… / 1430`, en 262 ms : compte présent et valeurs `[0x2a,0x0,0x2a]`. Elle n’a lancé aucun nouveau RPC, CXX, image ou ancien test JS ; elle préserve l’échec global précédent. Le root de cette fixture locale n’est pas authentifié par consensus.
