# Public isolated-fixture identity verifier

The two new repository files are `tests/capella/isolated-fixture-domain.mjs` and `.test.mjs`. The module is pure: callers supply the public manifest and a Map containing exactly five public artifacts. It has no filesystem, environment, signer, ledger or network access.

`verifyIsolatedFixtureDomain({manifest, artifacts, legacy})` expects format `nano-isolated-capella-fixture-domain-v1`, the coordinated explicit-operator-ledger schema, 65 indexed validator public keys, 64 indexed withdrawal public keys, and a new public transaction sender. The independent legacy input contains the old genesis validators root, exactly65 old validator public keys and the old transaction sender address. File binding paths are fixed to `genesis-validators.ssz`, `genesis-state.ssz`, `genesis.json`, `profile.json` and `initial.json`; path traversal and extra private artifacts are refused.

The verifier independently computes the SSZ root of List[Validator, profile registry limit] from 121-byte records, eight-field containers, sparse zero padding and a 256-bit little-endian length mix-in. It also computes full Capella BeaconState, ExecutionPayloadHeader and initial BeaconHeader roots. It verifies before-transition64-member registry bytes, immutable genesis validators domain, public credential hashes, key uniqueness/cross-role/legacy separation, current/next committee membership, sender funding, typed public reservations and SHA256/canonical identity bindings. It distinguishes the pre-transition genesis registry from the mutable initial post-block registry; the latter must retain the genesis domain rather than reproduce its registry root.

## Public controller and actual native export

`audit-public-export.mjs` reads exactly `isolated-domain.json` and its five fixed public artifacts from the supplied export directory. It additionally authenticates four pinned public historical files in the repository: the official Capella slots manifest/pre.ssz, historical public profile, and historical deposit.json. It imports only the hash-pinned frozen verifier under `balance-final`. It rejects symlink/alias inputs, nonregular files, duplicate JSON fields, source hash drift and file changes during reads. It does not list or open neighboring private files. The output JSON is created once with O_EXCL, outside the input and repository; arbitrary assertion values are omitted from failure diagnostics.

Usage (the second path must not exist):

```sh
node audit-public-export.mjs /absolute/public-export-directory /absolute/new-public-audit-receipt.json /Users/boris/Dev/blockchain-nano
```

The six expected export filenames are `isolated-domain.json`, `genesis-validators.ssz`, `genesis-state.ssz`, `genesis.json`, `profile.json` and `initial.json`. The optional third argument defaults to the repository above. No seed, scalar, env capsule, reservation ledger or signer is read or executed. The controller does not run the C++ exporter, node, duties or network.

The first actual native audit (`2b1d01/1`) reached the final genesis balance check and refused a canonical65-bit EVM sender balance. That was a verifier defect: account balances use uint256, while consensus/profile/clock quantities remain uint64. A dedicated EVM-balance parser now fixes only those account fields. Eleven new targeted cases passed (`0da003/0`):65-bit and maximum uint256 acceptance; uint256 overflow, noncanonical hex and wrong types refusal; the unchanged uint64 clock bound; and funded historical sender refusal. The original verifier/refusal/log remain intact.

The same actual native export then passed (`35bddb/0`) as `PASSED_PUBLIC_BINDINGS_ONLY`. All six export file hashes and four public historical file bindings are unchanged from the original refusal. The independently authenticated new genesis validators root is `0xfe0dc8b10d151359ca3836e844266bbbe45352a35374d87b5f6527a9ffa2d753`; campaign ID is `cb532955c358607d94e4e1074e26be4f4a235dd61b1a00ac2117129973a385ed`. Its original exporter execution belongs to the parent task; this child audited only the public output. See `actual-native-public-audit-balance-fixed.json` for every scoped result and `evm-balance-fix-receipt.json` for source and terminal bindings. No BLS cryptography, actual signature ordering, ledger consumption, journal import, live runtime, universal replay protection or production readiness is inferred.
