# Linux current-Core runtime relink worker (source proposal)

This proposal is Root-only source, not an executed qualification. It adapts the publicly packaged selected-helper worker 44c7294e0e26a30149a9142ace83a1014dcbb3477ce414e5920d021c9c8cd134 (25,229 bytes). The prefix before `sub main` is unchanged except its global deadline, 590 to 900 seconds. Its FD/path GNU nine-field checks, bounded SHA reads, alias guards, process-group cleanup, dependency parsing, stabilization and failure handling remain in place. The author has not run Perl, a compiler, a project program, Docker, SSH or Git.

Root invokes `/usr/bin/perl /controls/worker.pl --current-core-runtime-relink` in an existing immutable image. Four controls are read-only: worker.pl, recipes.json (INPUT.schema.json), source-expected.private.json, and core-pin.json. The source table maps physical /work or /old paths to known positive SHA256/byte descriptors; the Core descriptor has only sha256 and bytes. Root must bind those controls and the actual recipes to the retained producer results and original authorities before launching. Their declared source revision and image are checked for the supported values but are not authenticated by the worker alone.

The ARM owner is mac-docker, UID501/GID20, ELF machine183, image sha256:e30ce85e363309a64814c300fbf07b482e28b841c8f9577cba9b4e70070d37fb. Its Core is 35779b74ff3894d8857d06732caa801cb340381f4cf6dc5801074c7e372dbdf6, 41,053,984 bytes. AMD is vps-docker, UID1000/GID1000, machine62, image sha256:fd9b0bb98a63963dba141a820ab7a49c08e23afcfb7b5ea9ea939987d75d6f14, with Core1687f1876ea784006b0d687db0f94e3a49b01f8edaa3a599fdf942a9fc4d1525, 40,820,160 bytes. Root verifies actual container/image identity. /outputs must be a new empty physical directory, mode0700 and the selected owner; no diagnostic is written before that admission.

The exact ARM roles are nano, bootstrapImport, bootstrapAudit, stoppedCapture, lifecycleTool and lifecycleSubmit. AMD omits bootstrapImport. P2P is outside this worker: it does not link nano_core and has a separate retained qualification. The worker neither preprocesses, relinks, loads nor executes P2P. It does not accept exporter, extraRotation or arbitrary target names.

Each role has the same selected recipe shape as the old helper interface: role, source, compileFlags, linkPrefix, linkTail, reuse. `reuse` is mandatory and contains object and md descriptors (path, sha256, bytes under /inputs), plus dependencyPrefixMap. There is no compilation fallback. The two permitted prefix mappings are /overlay to /work and /outputs/third_party to /old/third_party, each at most once. Root must prove the retained object's actual producer, original full-nine identity and current project-source equivalence. A byte-only copy does not recover a historical identity. In particular the older AMD Tool object bound to header07993 is insufficient for current header668192: Root must provide the later qualified object's retained authority. Missing or mismatching authority refuses this batch.

For every role the worker runs one independent actual compiler -M with the supplied canonical semantic flags, current source and -MT/-o output control. No -MD or -MMD is run because every object and its genuine historical MD are reused. It reads that physical MD without editing, filtering or synthesizing it. It reports literal dependency equality, normalized-path equality and normalized equality after the explicit retained-prefix map separately. Only the last equality is required; a literal inequality remains visible. Current normalized paths must resolve to the same physical files as their literal spellings. All reached dependencies are stabilized before the link and held through the final fence. Unused entries in the Git source projection are shape checked but are not all admitted as compiler inputs.

Selected CMake add_executable and target_link_libraries PRIVATE nano_core declarations must occur exactly once. Tool requires exactly one NANO_TEST_SOURCE="/work" definition; the other roles require none, and all reject NANO_SYNC_FAULT. Every link tail has one /baseline/libnano_core.a, five archives total and two assembly objects. Root preserves the actual canonical link order and validates the retained non-Core inputs, rather than deriving provenance from the counts. Compiler flags and link prefix reject output/dependency/response-file and unsupported side-effect controls.

The worker performs ARM6 or AMD5 links using the retained objects and the already qualified current Core. It never compiles C++, runs ar, changes Core, configures CMake, builds an image or requalifies the143/142 Core member proof. Each new executable is chmod0500 before its first material observation, then receives at least three identical full-nine/SHA samples spanning at least2seconds. ELF architecture and ldd are checked, and loader paths are admitted before CLI execution. This demonstrates observed loading and entry to selected CLI branches, not all lazy symbols or the complete loader/SDK DAG.

Nano has two CLI probes: --help returns0 with the exact public two-line prefix and empty stderr; `rpc` without its required arguments returns1 with exact usage and empty stdout. Each helper has only its no-argument refusal, exact JSON or bytes as implemented by the current public source. These branches precede fixture/database/key/network access. This gives ARM7 or AMD6 program calls, of which6 or5 are expected argument refusals. The environment is replaced with PATH, HOME, TMPDIR, LANG and LC_ALL only; no inherited NANO, key, loader, compiler-control or runtime variables survive.

The global worker deadline is900seconds, every command is bounded to179seconds, each first stabilization to30seconds, each stream to16MiB and each file to512MiB. Existing held rows cannot settle or rebase. New executable rows can settle only against their known bytes before first admission. TERM/INT/HUP refuse and stop the worker's own process group with bounded TERM/KILL; no unrelated process is targeted. Root must reserve external cleanup time, keep named output volumes, mount every volume with volume-nocopy, inspect exact image/labels/mount ownership, and collect bounded logs before asserting the worker exit code. Root must also compare original retained guest rows before and after this invocation; the worker's fresh /inputs namespace alone cannot recover an old host or guest identity.

On success, result-public.json contains per-role object/software pins, the three distinct dependency comparisons, command counts and the SHA256/bytes of software-admission.private.json. The private binding retains Core, every selected object/MD/software row, reached guest materials, resolution guards and per-role results. It asserts no old authority refresh. Root must authenticate the descriptor bytes from this public result and join actual produced software rows without last-wins. The outputs are evidence for selected relinks, not the three campaign admissions.

Expected totals: ARM6M/0CXX/6links/6ldd/7CLI; AMD5M/0CXX/5links/5ldd/6CLI. Both have0ar,0Core compilation and0P2P commands. No prior test suites, startup/SST modes, database opens, real import/export, new signatures, seed/domain creation, node runtime, network, duties, common finality, campaign admission or production qualification is claimed. Historic failures and unknown bindings remain separate evidence. Root execution remains pending.
