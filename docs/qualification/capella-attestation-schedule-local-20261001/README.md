Source parent 0c09ca2, exact pending scheduler patch and hashes retained. One attestation opportunity now follows each background catalog (head/block, slashing, credential change, sync, exit). Every background kind remains present in any ten service starts; scheduler state is bounded and local to the peer. Existing peer ownership, global relay limit, per-peer send pacer, dependency handling, ACK/admission checks and timeouts are unchanged. The 100 ms poll interval is unchanged. This is prioritization, not a higher network traffic allowance or consensus change.

Four new scenarios pass on native and ARM64: long-run fairness, every starting phase, peer/session independence, and modeled catalog-delay bound. Modeled delays are not measured transport performance. Real distributed-cli passes in both environments (two actual daemons, 32 validators each, common finalized epoch 2 in three stable observations, healthy signers/clocks, clean stops). Category completion counts show all background kinds remain served and attestations interleaved; counts are events, not admitted payloads or unique blocks. Exact roots and admissions retained in result.json.

Core and transport/dependency helper sources remain unchanged from their previous qualified revisions; they were not blindly retested. Only the new scheduler and changed daemon were rebuilt; real integration runs qualify the changed dispatch path. AMD64 and WAN remain unqualified. Existing portable 86af5f8 images remain old immutable candidates; modified native/ARM64 P2P binaries must not inherit their provenance, and the ARM64 volume marker is intentionally stale until qualification/provenance update.
