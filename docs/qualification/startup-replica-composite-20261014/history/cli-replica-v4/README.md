# CLI V3 : proposition source non exécutée

Le CLI ne fait plus aucun OpenForReadOnly/ChainStore ReadOnly sur le chemin des copies opérationnelles. Ses invariantRO et cold-readbacks utilisent uniquement une capability privée `SealedReadonlyReplica`, matérialisée intégralement sous output700 dans un nouveau sous-dossier aléatoire. Originaux et replicas ne sont jamais DBRW. Pair/typed reopen restent ReadWriteExisting sur les deux copies, avec le vrai LOCK et la preuve/twoNEXT/CAS historiques inchangés.

La capture tient les DirectoryFD et, durant chaque lecture/copie, les FileFD O_NOFOLLOW. Les scans complets SHA256+longueurs+identités/nlink/modes/mtime/ctime/ensemble avant-après sont stricts ; les nouvelles feuilles sont0600, directories700, inodes distincts. Les modes sources sont vérifiés mais ne sont pas annoncés identiques aux modes privés des replicas. Aucune tolérance LOG/WAL, timestamp ou SDK n'est ajoutée : une mutation détectée, y compris pendant OpenForReadOnly, refuse. Les buffers sont64KiB ; files+directories comptent dans le budget entries (budget inventoryFiles existant), profondeur128/paths4096 ; bytes et callback global de durée existants restent imposés. L'absence de writer concurrent reste une condition externe, pas une vérité créée par un scan stable.

Toutes les replicas sont revalidées et nettoyées explicitement avant le Pair suivant et avant complete.json. Cleanup ne parcourt que les noms/inodes effectivement créés, via heldFD/unlinkat et sans suivre les liens. Une substitution ou un cleanup incomplet refuse ; un scratch privé peut alors demeurer pour diagnostic. Aucun output préexistant/source/copie n'est supprimé. Les sources du request continuent leurs propres inventory checks. stdout, request/NEXT schema, relations current/next et ordre fsync restent exacts. Aucun rollback d'un préfixe durable déjà publié sur les copies en cas de refus final.
