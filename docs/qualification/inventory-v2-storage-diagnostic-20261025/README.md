# Divergence Anvil : feuille de stockage zéro expliquée

Le rejeu exact initial reste [FAILED à la transaction3](../inventory-v2-native-raw-differential-20261025/README.md). Les 62 transactions suivantes n'ont pas été comparées par ce rejeu. Ce dossier explique l'écart observé sans convertir son verdict en réussite globale.

Un diagnostic distinct a reproduit seulement les trois transactions originales : mêmes octets signés, gas et racines Native, puis les deux racines Anvil identiques et la même troisième divergence. La lecture de14comptes et40slots connus ne trouve aucune différence de nonce, solde, code, codeHash ou valeur connue. Seuls les storageRoot des deux endpoints diffèrent. Le [contrôleur](prefix-controller.json) et son [reçu externe](prefix-root-result.json) confirment les sorties0,19requêtes et groupes absents. Le programme de lecture, lié au cœur existant, ajoute seulement deux champs readonly et bornés ; son [build](diagnostic-helper-build.json) ne recompile pas le cœur et ferme836FD.

L'[oracle indépendant](canonical-oracle-analysis.json), qui utilise ethers RLP/Keccak sans importer Nano, retrouve les racines Native pour les14comptes. Il authentifie les accountProof au stateRoot Anvil fixé séparément, puis40preuves de valeurs aux storageHash ainsi authentifiés. Sur les endpoints, les15valeurs non nulles donnent dans les deux calculs canoniques `0x750ab8681ac5b3ab692d8a97c51f40175cc67bade6e4643633d3b9255d6f4b61`, tandis qu'Anvil engage `0x8d5b145a989664034bda51b686fca0d151aa7ebea67147b7a2007557122544a2`. Ce premier calcul seul n'excluait pas des entrées supplémentaires de référence.

Le [calcul séparé de la feuille zéro](zero-slot8-analysis.json) départage cette possibilité : ajouter uniquement au slot8 une feuille dont le contenu est RLP(0), `0x80`, produit exactement le root Anvil pour chacun des deux endpoints. Les chemins dérivés sont ensuite vérifiés contre ces mêmes racines de référence authentifiées : la présence de cette feuille zéro est prouvée dans leurs engagements. L'état et le calcul canoniques Native restent intacts. L'exclusion des zéros est conforme au [traitement de stockage EELS](https://steel.ethereum.foundation/docs/execution-specs/library/execution_testing_test_types/). La [source officielle Anvil1.5.1](https://github.com/foundry-rs/foundry/blob/v1.5.1/crates/anvil/src/eth/backend/mem/state.rs#L24-L35) construit son trie depuis toutes les entrées du cache, sans filtre des valeurs zéro. Les preuves et ce chemin source établissent ici une divergence du calcul de racine de cette référence ; aucune correction du cœur Nano n'est justifiée par cet écart.

Les calculs offline ont leurs sorties effectives0, respectivement22/22 et23/23FD fermés, en Docker AMD64 existant sans réseau ni nouveau build d'image. Ils ne qualifient pas la finalité de la référence, un inventaire général de tous états possibles, les62transactions restantes, les en-têtes/RPC ou la conformité EVM générale. L'écart de324gas entre les deux anciens scénarios à adresses/calldata différents reste séparément inexpliqué. Les [entrées et empreintes](inputs-public.json) permettent de reproduire ces calculs sur les seuls comptes synthétiques publics.
