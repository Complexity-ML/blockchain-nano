# Observation Base : projections RPC sérielles qualifiées en unités

Le 16 octobre 2026, Root a qualifié le correctif de l’observateur depuis la base source `d6b6fee31c5d07e26ec7f2278e1ac012322cceff`. Les cinq requêtes de contrôle final sont désormais attendues et projetées successivement. Un appel suivant ne peut plus réécrire, avant sa projection, une réponse déjà reçue par référence depuis un cache partagé.

Le [TAP causal conservé](evidence/baseline-stdout.tap) montre trois divergences que l’ancien code accepte à tort : header canonique remplacé, ancien checkpoint finalisé réécrit et second reçu altéré puis restauré. Les trois assertions de refus échouent avec `Missing expected rejection`, entraînant l’échec de leur parent : **4 tests, 4 FAIL attendus**, aucun skip. Le [fichier candidat complet](evidence/candidate-stdout.tap) termine à **35 PASS**, soit **33 feuilles et 2 parents**, avec zéro échec, annulation, skip ou todo. Les trois nouveaux cas contrôlent aussi un pic de concurrence égal à un et les dix mêmes appels du chemin concerné, sans retry ni repli vers `safe` ou `latest`.

La [qualification Root](evidence/qualification-public.json), le [résultat Linux](evidence/stdout.public.json) et la [fence hôte](evidence/host-input-fence-public.json) confirment treize entrées hôte inchangées. Les quatre copies Linux conservent leurs neuf champs et SHA ; les sept répertoires restent identiques après trois observations, dont une stabilité de **2 115 ms**, puis après les deux phases. Le wrapper dure **2 332 ms**, la [commande Root](evidence/command-public.json) **4 029 ms**. Les groupes enfants sont absents sans arrêt forcé et le conteneur est absent. Le raccord du champ `format` a été corrigé en revue avant exécution : ce n’est pas un échec de test supplémentaire.

Cette preuve utilise des RPC injectés en mémoire, sans réseau, transaction, compilation C++ ou construction d’image. Elle démontre une collision synchrone de cache ; aucun exploit équivalent du transport HTTP courant, qui parse de nouveaux objets JSON, n’est démontré. Le transport RPC inchangé et les autres suites n’ont pas été rejoués.

La sérialisation peut augmenter la latence ; l’observation n’a toujours pas de timeout global. La canonicalité et `finalized` restent des assertions RPC sans dérivation L1 authentifiée ni preuve d’inclusion du reçu. `cryptographicFinalityVerified:false`, `eligibleForMint:false` et `productionQualified:false` restent inchangés. Authentification du message, domaines destination/actif/montant/bénéficiaire, idempotence persistante et reprise atomique restent ouverts ; aucun bridge ni mint n’est qualifié.
