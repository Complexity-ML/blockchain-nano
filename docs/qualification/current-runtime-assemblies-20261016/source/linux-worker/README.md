# Linux selected helpers against the current Core

This is a Root-only **source proposal**, not an executed qualification. The author has not invoked Perl, compilers, project programs, Docker, SSH, or private inputs. It adapts the public `complete-nano-cross-arch-20261016/source/linux-worker/worker.pl` (`b1eb3cabeb5778b8876daf72cf85946ed839d2da56ecd49476cabdaaaf2dc581`, 15,789 bytes). Its FD reader, GNU stat string rows, process-group runner, deadlines and explicit failure reporting are retained. The old Nano-specific main is replaced by a finite selected-helper loop.

Root supplies a new empty physical `/outputs`, mode 0700, owned by the selected UID/GID, a read-only `/work` project projection, `/old` selected library/build inputs, `/baseline/libnano_core.a`, optional retained objects/MD files under `/inputs`, and four read-only control leaves. No global SDK, configure, Core rebuild, archive creation, old test suite, real import/export, seed, key, database, network, duty or campaign operation is requested. Source and selected library mounts must be read-only; the worker does not create or inspect Docker resources.

## Exact input contract

`/controls/recipes.json` has exactly `format`, `owner`, `uid`, `gid`, `imageId`, `elfMachine`, `programs`. The format is `nano-current-linux-selected-helpers-recipes-v1`. ARM is `mac-docker`, 501:20, ELF machine 183, image `sha256:e30ce85e363309a64814c300fbf07b482e28b841c8f9577cba9b4e70070d37fb`. AMD is `vps-docker`, 1000:1000, machine 62, image `sha256:fd9b0bb98a63963dba141a820ab7a49c08e23afcfb7b5ea9ea939987d75d6f14`. Root verifies the actual image identity: the worker only validates this declared tuple and ELF machine, and reports `imageIdentityVerifiedByWorker:false`.

Each unique selected program has exactly `role`, `source`, `compileFlags`, `linkPrefix`, `linkTail`, `reuse`. Roles are `bootstrapImport`, `bootstrapAudit`, `stoppedCapture`, `lifecycleTool`, `lifecycleSubmit`; AMD excludes Import. Source paths are fixed to their current public TUs by role. `compileFlags` is the canonical semantic compile argv, beginning with `/usr/bin/clang++`, without source, `-c`, output or dependency-control arguments. Include paths and definitions are already argv elements. `linkPrefix` begins with that same absolute compiler and contains the canonical prefix flags. The actual command is `linkPrefix + [object, "-o", newExecutable] + linkTail`. The ordered tail is preserved verbatim; `/baseline/libnano_core.a` must occur exactly once. Root derives and authenticates every remaining archive/object/library input from its actual selected recipe, including the actual ARM two ASM or AMD two LLVM objects. The worker does not replace an actual tail with a guessed universal 5-archive recipe or configure targets globally.

Tool must contain the exact single argv element `-DNANO_TEST_SOURCE="/work"`; other helpers have no such macro. None accepts `NANO_SYNC_FAULT`. Root derives any current Tool macro delta from the public CMake target and preserves the corresponding retained producer source binding. Fixtures referenced outside the preprocessor closure remain Root's explicitly pinned `/work/tests/fixtures` projection; Root stages and checks their known bytes outside this worker; unused fixture files are not added to the worker's selected dependency admission. No fixture is opened by the worker's no-argument probes.

`reuse` is null, or exactly `{object:{path,sha256,bytes}, md:{path,sha256,bytes}, dependencyPrefixMap:[...]}`. Both paths are normalized `/inputs/...` leaves (or deeper physical paths); both descriptors are required and checked before first guest admission. Allowed comparison mappings are only `/overlay` to `/work`, and `/outputs/third_party` to `/old/third_party`, each at most once with a component-prefix match. Mapping changes only the retained MD comparison; it never changes the retained MD bytes, object, compiler argv or link argv. Root retains the original host full-nine/SHA authority and independently checks that the staged old source and macro bindings justify reuse. A guest inode is not presented as that old host inode.

`/controls/source-expected.private.json` is a physical normalized guest-path map `{path:{sha256,bytes}}` for all selected `/work` project/generated inputs and `/old` inputs. Each newly reached path in those roots must have a matching descriptor. Root proves Git/current-source equivalence and original producer authority separately; this map is a staged known-byte control, not a recovered historical source admission. `/controls/core-pin.json` is exactly `{sha256,bytes}` for the current archive at `/baseline/libnano_core.a`. `/controls/worker.pl` is the frozen proposal. Root pins/fences the controls and tools outside the worker as well. `INPUT.schema.json` describes recipes with definitions for the two other JSON controls; the finite runtime checks listed there are also required.

## Operations and dependency comparisons

The worker installs an explicit child environment: PATH `/usr/bin:/bin`, HOME `/outputs`, TMPDIR `/tmp`, LANG and LC_ALL `C`. It inherits no NANO, loader override, compiler-control, key or fixture variables. This is a narrow known-recipe runner, not a general compiler-argument sandbox. Root must supply only its independently authenticated canonical recipes.

The selected five or fewer TUs, retained inputs, link file inputs, Core, controls and directly invoked tools receive at least three equal full-nine/SHA samples spanning at least two seconds, with a 30-second per-admission bound. Known selected source bytes and retained object/MD descriptors are checked on every sample. The full source-expected map is shape/path validated but unused project files are not repeatedly statted or admitted. Each actual normalized dependency reached by M is then stabilized and pinned before CXX/link. Once held, a row is compared strictly and never refreshed. Logical-to-physical resolutions are also retained and fenced. GNU FD/path stat supplies nine **strings** `[dev, ino, modeHex, nlink, uid, gid, size, mtimeText, ctimeText]`; no numeric comparisons mutate these values. Built-in lstat fields are used separately for ownership/mode gates.

For each role there is exactly one independent compiler `-M`. For reuse its normalized set must equal the normalized, explicitly remapped retained MD set; the original literal sets and their counts remain visible. Lexical normalization removes dot/duplicate-separator components and deduplicates; current raw names must resolve to the same file as their normalized names, preventing a symlink/`..` semantic change. This is not a claim of literal path equality or recovered historical alias bindings. With no reuse, only that TU is compiled using **canonical `-MD -MF ... -MT ... -o ... -c`**, not `-MMD`. Its real generated MD normalized set must equal the independent M set. Literal equality is separately reported and is not assumed. There is no second preprocessor scan merely to compensate for an MMD policy.

New object/MD outputs are set to 0400 before first stable admission; the new executable is set to 0500 first. New products require three equal full-nine/SHA samples over at least two seconds; their initially known SHA/bytes cannot change while metadata settles. The worker then links once, checks ELF64 little-endian architecture, invokes `ldd`, holds the resolved selected runtime files in the same container, and executes the helper with **zero arguments**. Compilation SDK dependencies are held after M and before CXX/link; additional runtime files are admitted after ldd and before the refusal probe. These are explicitly current container observations, not old SDK authority or full loader closure. Existing rows remain strict across each command and the final fence.

Fixed public-source oracles are used: Import/Audit/Capture emit their exact JSON argument-refusal objects to stdout with empty stderr; Tool emits its fixed `usage: --audit ...` stderr with empty stdout; Submit emits its fixed refused-event stderr with empty stdout. Every one must exit 1. No `--help`, self-test, path argument, environment-based export or default exporter scenario is run. These checks demonstrate ELF loading and reaching the early CLI guard; they do not prove all lazy symbols, future runtime, real import65, audit journals, actions, payout, HTTP or duties.

## Bounds, outputs and limits

The global monotonic deadline is 590 seconds; each command has a 179-second ceiling and two 16 MiB stream limits. Individual FD reads are bounded by 512 MiB, captured JSON/log reads normally 16 MiB. Child groups have bounded TERM/KILL cleanup, including the leader-before-setsid race and surviving groups after normal leader exit. TERM/INT/HUP use the failure/final fence path. Output writes are enabled only after empty directory, mode and owner checks. Failures export only static stderr and a private typed refusal; command attempts are counted before launch, without converting a failed command into an expected successful operation.

The successful public result contains per-role source-independent counts, literal/normalized/remapped equality flags, product SHA/bytes, exact Core pin, and SHA/bytes of the new private `software-admission.private.json`. That admission retains object/MD/executable rows, all guest held inputs and resolution guards. Root must preserve the producer-returned descriptor pin before downstream use. It also receives private command argv/logs, initial observation rows and final SDK/input rows inside the new output namespace. No private content is printed.

There is no worker claim for original host-nine recovery, Docker image verification, full CMake equivalence, Core member requalification, complete SDK/loader DAG, lazy symbol closure, campaign admission, runtime/finality or production. These remain false. Expected routes today are ARM two reused objects plus three new TUs, and AMD three reused objects plus a new Tool TU; this is Root-provided evidence-dependent selection, not a hardcoded promise or a reason to recompile an admitted object. The proposal itself has not been executed or syntax-checked with Perl.
