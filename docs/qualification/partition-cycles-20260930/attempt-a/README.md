# Cycles de partitions — tentative A, verdict de délai

Deux coupures effectives, de 96 puis 192 secondes demandées, sur les images
candidates finales ARM64/x86-64 avec Mac natif. Trois processus sur deux hôtes,
64 clés synthétiques, Capella/Shanghai. Le premier cycle passe. Le second
manque le délai initial de 180 secondes, puis retrouve une finalité commune
plus récente lors de l’observation tardive. Ce dépassement reste un échec.

Les durées exactes et événements sont dans `deadline-result.json`. Les deux
archives compressées sont des captures intermédiaires ; la campagne poursuit
la fenêtre de stabilité finale et aucun état terminal n’est encore revendiqué.
La cause du délai n’est pas encore établie. Aucune prolongation du critère
initial, relance, modification de profil ou qualification globale de production.
