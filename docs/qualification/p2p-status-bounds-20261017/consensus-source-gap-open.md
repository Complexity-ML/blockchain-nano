# Consensus : sortie admise perdue lors du pruning après réorganisation

17 octobre 2026 — revue SOURCE publique uniquement ; aucun code modifié, test lancé, entrée privée lue ou campagne proposée. Défaut identifié dans la condition de retrait de la file ; scénario API causal à exécuter seulement si Root le retient.

Le socle natif possède déjà dépôts/admission, sorties volontaires, sanctions et retraits. Le dernier état documentaire conserve toutefois le cycle complet et la reprise comme non qualifiés ([PRODUCTION-GOAL.md:23–25](/Users/boris/Dev/blockchain-nano/docs/PRODUCTION-GOAL.md:23)). Ce constat précis concerne la durabilité d’une sortie déjà acceptée, sans modifier règles économiques ni modèle de consensus.

## Joint fautif et effet

- [consensus_capella_reactor.cpp:607](/Users/boris/Dev/blockchain-nano/src/consensus_capella_reactor.cpp:607) authentifie la sortie sur la tête, mémorise ses octets, la clé et `admission_root`, puis publie le checkpoint avant de retourner true.
- [Ligne285](/Users/boris/Dev/blockchain-nano/src/consensus_capella_reactor.cpp:285) réancre à la seule racine finalisée lorsque cette racine d’admission disparaît. Si `exit_key` refuse, elle **efface l’opération**. Or [exit_key:60](/Users/boris/Dev/blockchain-nano/src/consensus_capella_reactor.cpp:60) refuse aussi lorsque `exit.epoch` dépasse l’époque du post-état finalisé. Un état finalisé plus ancien ne prouve ni signature invalide, ni sortie déjà traitée, ni changement de clé. La ligne284 distingue déjà ces retraits définitifs.
- [prepare_capella_pruned_store:389–395](/Users/boris/Dev/blockchain-nano/src/consensus_capella_fork_store.cpp:389) conserve seulement la nouvelle ancre et ses descendants : une branche abandonnée peut perdre son état d’admission même si celui-ci était plus récent que l’ancre. [prune_finalized:1098](/Users/boris/Dev/blockchain-nano/src/consensus_capella_reactor.cpp:1098) publie réellement ce candidat. L’archive sans sortie reste alors valide et peut être réouverte : aucune vérification ultérieure ne reconstitue l’opération effacée.

C’est une perte de file acceptée, pas une fausse sortie ni une preuve de perte de fonds. Une resoumission externe peut rétablir l’opération ; le nœud ne la conserve plus de lui-même. Le chemin voisin des preuves de proposeur [lignes299–303](/Users/boris/Dev/blockchain-nano/src/consensus_capella_reactor.cpp:299) refuse explicitement une réancre indécidable au lieu d’effacer la preuve.

## Un scénario nouveau, par les vraies API

1. Reprendre les petits propriétaires indépendants du banc de sortie/pruning. Utiliser un validateur genesis, même index/clé sur les deux branches, actif de longue date. La branche B est tête à l’époque E ; admettre une sortie signée `exit.epoch=E` sur le seul suiveur, sans l’inclure dans les blocs du producteur. Vérifier true, `signedExits`=1 et octets exacts après réouverture.
2. Réorganiser vers A et y finaliser F, **F<E**, sans sortie, sanction ou changement de clé du validateur. B doit avoir divergé avant F alors que F n’était pas encore finalisé : ne pas construire une réorganisation interdite sous une ancre déjà finalisée. La tête retenue A atteint au moins E ; la sortie y reste applicable.
3. Si des votes récents de B empêchent le pruning, avancer normalement l’horloge jusqu’à leur expiration, en gardant F inchangé : [tick:679–685](/Users/boris/Dev/blockchain-nano/src/consensus_capella_reactor.cpp:679). Ne pas retirer les votes par mutation de fixture ; respecter également la borne `current_epoch−min_seed_lookahead−1` du pruning.
4. Appeler `prune_finalized()` ; vérifier que B disparaît, que tête/finalité/clé/soldes restent cohérents et que la sortie n’a pas été incluse. Ancien code attendu : `signedExits` tombe à zéro parce que `exit_key(F)` voit un futur E. Oracle corrigé : aucune réussite de pruning ne doit perdre les octets ; après réouverture la file reste intacte et une proposition valide peut inclure la sortie une seule fois. Si la réancre n’est pas démontrable, refus/différé sans mutation du checkpoint, jamais effacement silencieux.

Les tests existants [pending-pruning:579–584](/Users/boris/Dev/blockchain-nano/tests/test_capella_transition.cpp:579) couvrent une progression linéaire avec état finalisé devenu admissible ; le test [réorganisation:2811–2826](/Users/boris/Dev/blockchain-nano/tests/test_capella_transition.cpp:2811) conserve l’archive sans ce pruning. Leurs qualifications restent acquises : [élagage natif1/1](/Users/boris/Dev/blockchain-nano/docs/qualification/capella-exit-pending-pruning-20260929/README.md) et [réindexation après dépôts](/Users/boris/Dev/blockchain-nano/docs/qualification/capella-exit-reindex-20260929/README.md). Le joint reorg + ancre finalisée antérieure à l’époque de sortie + suppression de la racine manque.
