# Capella duty readiness — qualification publique limitée

Les sources passent une invocation publique sur Docker Linux ARM64 et AMD64 chacune : huit groupes plus résumé, dix-huit lignes JSON au total, vingt-deux appels CLI (quatre observations acceptées, dix-huit refus), deux événements de cancellation observés et zéro CTest. ARM : 3,595 s / 24 248 KiB ; AMD : 12,807 s / 25 720 KiB. Les durées portent sur le consumer, pas sur un débit de nœud. Le plafond reste 131072 KiB / 180 s ; chaque campagne reste bornée à 400 s.

L’audit ARM lit directement le log public, son audit sémantique et son terminal. AMD est une attestation ROOT filtrée in situ : logs, métadonnées, objets, ELFs et données bruts restent VPS. Le parser V5 strict impose les mêmes groupes, onze enfants, deux observations acceptées, neuf refus et un événement par architecture. ARM crée douze signatures exclusivement synthétiques de bootstrap ; le fichier AMD filtré n’exporte pas ce nombre exact et garde la borne de 1024. Aucun signer/provider ni clé privée opérationnelle n’est utilisé. Les seules clés de signature utilisées en mémoire appartiennent aux fixtures synthétiques publiques.

`nano-capella-duty-readiness --observe REQUEST SHA256 REPORT SCRATCH` authentifie les CURRENT PRIMARY/WITNESS, leur fermeture complète et le lien à l’exécution canonique sur des répliques physiques readonly indépendantes. Il rejoint la projection de configuration et le rapport antérieur de journaux à une preuve original-before séparée ; les inventaires des journaux restent exacts sans rouvrir leurs bases. Il prépare localement les contextes HEAD, epoch cible, block et sync, distingue disponible, incomplet, inéligible et normalement non assigné, et protège gaps/chunks/retargets/UTC/deadline/RSS. Le rapport reste détenu0600. La sortie typée ne porte que comptes, ressources et diagnostics fixes. `probeCompleted`, contextes complets et éligibilité sont distincts ; `resumeAuthorized` reste toujours false.

`config.genesisHeaderVersion` absent ou entier1 conserve le codec et le hash historiques. Entier2 choisit explicitement les deux racines MPT canoniques pour un nouveau Genesis. Le premier groupe vérifie hash CB532 a055…, racines natives et indépendantes, roundtrip JSON, modification limitée aux deux champs, input inchangé et rejet des versions/types invalides. La fixture porte le tag2 dans les mêmes bytes JSON consommés par la CLI ; aucune normalisation après parsing n’est utilisée comme autorité. Les constantes empty-trie/transactions/receipts56e81f… et empty-list1dcc… sont définies dans [le fichier officiel go-ethereum `hashes.go`](https://github.com/ethereum/go-ethereum/blob/master/core/types/hashes.go). Aucun Genesis, checkpoint ou profil existant n’est migré.

Les deux builds corrigés remplacent seulement chain.cpp dans l’archive143 (142 membres repris), compilent le consumer et relient deux ELFs. L’objet CLI est repris après vraie fermeture M/MD/source/header/SDK, le shim existant reste exact. Les recettes sont manuelles ; le nouveau CMake est seulement livré comme source, sans configure/install/natif qualifié. Le premier build ARM a bien compilé/relié puis son contrôleur a refusé tardivement une mutation d’input dont le chemin n’a pas été enregistré. ROOT a réaudité les buffers/sources/inputs/SDK puis les artefacts ont été admis avec ce refus explicite ; cela ne transforme pas l’ancien contrôleur en exit0. L’essai précédent0,223s/0row/0CLI et son exception perdue, les refus metadata et les anciens sources restent historiques.

Ce lot ne prouve aucune duty réelle, signature/livraison historique, ascendance des digests, nonce, finalité commune ou reprise runtime. Le rattrapage clock-only ancien sous ELF/archive142 reste une preuve séparée ; il n’est pas transféré au cœur143 ni à une queue durable-v5 non vide. Le cache strict4MiB ne passe ici qu’une fixture courte : le refus de longue finalisation reste ouvert. Originaux Mac manquants/NAS non autorisé, V37FAILED, WAN A, natif/install/nœud complet, trois nœuds et duties/finalité commune, powerloss/WAL/reindex, audit de sécurité externe et bridge/Base/Doppler restent ouverts. Shanghai demeure actif, aucun fork ni statut EIP/CSV n’est promu, production non qualifiée.

Les cinq overlays et quatre nouveaux préfixes sont byte-épinglés. Chaque préfixe est ajouté au-dessus du corps historique entier ; l’unique CSV et les autres matrices restent exacts. Le paquet contient uniquement sources C++/CMake, petits résultats publics et historiques ; aucun driver Python ROOT, rapport privé, requête privée, clé, base, objet, ELF ou archive n’est importé. Voir [les résultats structurés](scoped-results.json) et [le contrat de préservation](preservation.json).
