# Sortie conservée après réorganisation et pruning — Native et Docker ARM, 17 octobre 2026

**Le défaut est reproduit sur l’ancien Core ; les deux scénarios ciblés passent ensuite sur le Core corrigé Native.** D07 démontre une sortie signée admise, jamais incluse, perdue après suppression de son état d’admission lors d’un pruning pourtant réussi. D10 conserve cette sortie et couvre séparément le différé du pruning lorsqu’aucun état retenu ne peut l’authentifier. Les deux régressions Native existantes passent également dans D13 ; ARM02 passe maintenant les deux nouveaux scénarios sous Docker Linux ARM64. Les deux régressions Linux et AMD restent attendus ; aucune campagne ni production n’est qualifiée.

Les vrais blocs signés importés font avancer la finalité après admission :16 blocs A, 2 blocs B, sortie d’époque 4, état finalisé 2 et tête 4, même clé, aucune inclusion et aucun vote retenu. Le pruning retire la racine B sans changer la tête, mais la file passe 1→0 ([sortie](evidence/D07/causal.stdout.log), [diagnostic](evidence/D07/causal.stderr.log)). Pic RSS 81472 KiB et 287 signatures synthétiques, sous les plafonds 128 MiB/1024. Ce retour 1 est la preuve du défaut, pas un PASS produit.

[D10](evidence/D10/result-public.json) passe les deux sélecteurs, chacun dans un processus distinct :

- `--exit-reorg-prune-self-test`, 14,602 s : file 1→1, vrais pruning/réouverture primaire-témoin, doublon sans nouveau token et réinclusion par proposition normale ; archive conservée avant finalisation. 289 signatures synthétiques.

Ce scénario ne prétend pas que la sortie était déjà incluse dans la tête.

Le correctif source `38649222…` réemploie les contrôles d’authentification existants : seuls une identité remplacée ou une sortie déjà programmée dans l’état finalisé retirent la demande ; sinon, il faut un état retenu vérifiable, ou différer. Les sources intégrées par Root et leur identité ne constituent pas, à elles seules, une qualification d’un autre environnement.

D10 reprend les compilations achevées D09 : **0 CXX nouveau, 1 lien**, puis deux tests 0. La [preuve d’archive](evidence/D10/archive-one-member-proof.json) vérifie 143 membres objets ordonnés, dont 142 byte-identiques ; seul `consensus_capella_reactor.cpp.o` est remplacé. Nouveau Core `3401bf777c09f98b2ce4c035c336176dcdbe3097926c232f524670cff697fc37`, 29252992 B, au lieu du Core Native `7052b226…`, 29247704 B. Cette fonction de comparaison ne vérifie pas elle-même les neuf champs du fichier archive ni la sémantique des tables de symboles ; le reçu D10 atteste séparément les entrées/produits tenus inchangés.
