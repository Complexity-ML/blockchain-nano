# Inspection hors ligne des votes de WAN N

Base native arrêtée, ouverte en lecture seule, checkpoint final contrôlé contre le reçu public indépendant. Un inspecteur C++ temporaire extrait les attestations de 113 blocs archivés ; le CLI officiel `audit-capella` rejoue en lecture seule 114 blocs avec l'ancre, 328604 octets archivés et une transaction, et vérifie états, signatures/transitions, index et reçus canoniques. Head, nombre de blocs et octets concordent entre les deux lectures. Aucun runtime n'est redémarré ni DB modifiée. L'inspection utilise le cœur eb8d3ed contenu dans d1ca5ca ; la campagne mesurée exécutait 1e1e732.

Époque 13 : 6 occurrences de bits incluses, dont 5 visant la racine de frontière retenue. Époque 14 : 60, dont 38 visant la frontière retenue et 22 une autre racine. Époque 15 : 64, dont 58 visant la frontière retenue. Ce sont des occurrences de bits, pas une nouvelle mesure de stake ou un décompte général de validateurs uniques. Les 38 occurrences de l'époque 14 sont insuffisantes pour représenter 43 validateurs distincts de poids égal dans cette fixture de 64 ; les votes de cible concurrente ne doivent pas être additionnés pour prétendre au quorum de la racine canonique.

Cette extraction explique l'absence de participation suffisante à la cible canonique 14 dans les blocs finaux, mais ne détermine pas seule pourquoi les votes se sont répartis ni quels messages ont été refusés/retardés. Aucun rejeu des votes hors bloc ou du choix historique de branche. La première tête commune observée vers 130845 ms muraux, puis finalité 15 vers 180127 ms muraux, restent des observations non simultanées ; la durée monotone originale exacte manque. M/N restent en échec et la production n'est pas qualifiée.

Rejets conservés : la première requête d'audit portait un champ `maximumBytes` supplémentaire dans la référence de profil et a été refusée ; la requête conforme à deux champs a ensuite passé. Le premier inspecteur tentait de décoder directement l'enveloppe durable comme un snapshot simple et a été refusé ; le code final utilise le restaurateur officiel `CapellaDurableReactor`, avec l'engagement indépendant. L'inspecteur est un outil diagnostic pour cette archive, pas une nouvelle API de production.
