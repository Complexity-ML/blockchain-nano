## Functional change and final observation boundary

The new callback-only sequence retains the first Error object. Later failures,
including failure-log publication errors, receive separate stage/phase results.
Public summaries contain fixed stage names/booleans and no error/private values.
It cannot grant campaign, recovery or signing permission.

The actual fresh finally block now independently attempts:

1. Stop every owner requiring a stop; collect exact retained stopped receipts.
2. Join both managed native handles. Each success is remembered only after
   `!forced` and `childAbsent`. Both clean successes are required for every
   capture. A failed owner stop cannot be bypassed by an old receipt; a Docker
   capture also requires the existing exact owned-runtime stopped-state check.
3. Capture owners independently and preserve their immediate commitments.
   Three current successful captures and the unchanged exact public receipt
   validator are required for combined publication, before lifecycle closing.
   Rotation/restored journal audits cannot run without all three captures.
4. Attempt lifecycle closing without weakening its complete-live-stage and
   terminal C++ validation. The C++ output is a scoped replay result; overall
   campaign success still requires every applicable terminal stage.
5. Check Linux/bootstrap, selected software, retained inputs and new outputs;
   publish stopped receipts; perform exact owned cleanup and partition cleanup.
6. Check Linux/bootstrap and software after that cleanup; inspect/clean only
   newly owned late probes. A late stop makes the campaign FAILED.
7. **After those last software probes and their cleanup**, independently check
   the original source-copy, artifact, index and known-file families using their
   unchanged pins and predicates. The original source-copy program still
   excludes resumed copies and checks the retained stopped source roots only.
8. Inspect/clean only the new readonly operations added by step7, under the
   same exact name/image/UUID guards. Any late stop is FAILED. Do not rerun
   software, a previous fence family or an earlier qualification.
9. Verify owned container absences, retained held full-nine/SHA and new outputs,
   and process joins. Publish a stage report, fence its output, then publish the
   final result. Publication cannot circularly include its own write/fence;
   Root must separately join the actual process and inspect its terminal exit.

All independent checks continue after an earlier refusal; prerequisites for
opening journals remain strict. No deadline, budget, new identity or old
admission is refreshed. No image rebuild, pruning or old-domain retry is added.
The complete prospective save/observe/fence predicates are unchanged.
