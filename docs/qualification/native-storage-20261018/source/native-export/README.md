# Native04 public physical export — source proposal

This package is source only, unexecuted by its author. It exports the **existing** public synthetic Native04 cohort without running C++, opening a DB API, producing blocks, constructing keys or signing. It does not requalify Native04/05 host failures. No original source, authority or database is changed. Root alone fills and pins the separate effective control, freezes the source, admits inputs and executes it.

`runner.py` is the one operational entrypoint. `cohort_common.py` is a byte-exact independent copy of the reviewed reverse-cohort helper (`09422e11…`, 10,200 bytes); the old package is not imported or modified. The runner checks the helper’s externally known bytes and its explicit Root descriptor before compiling those bytes into a `ModuleType` with a non-main name. It sets `sys.dont_write_bytecode=True`; no unvalidated import or pyc selection is used. Only Python’s standard library is needed.

## Raw copy and new carriers

The source is read only. A manual USTAR archive prefixes its entries with `public-cohort`; it normalizes transport ownership to1000:1000 and modes to0700/0600, omitting PAX/GNU extensions, symlinks, hardlinks, devices, xattrs and AppleDouble data. Original file payloads are copied byte for byte. The unchanged helper scans the archive **without extracting**, validates all69 entries, the independently pinned manifest/profile, explicit parent structure and the eight exact C++ portable inventory hashes. Source FD9/SHA is fenced before and after copying and throughout output admission.

Exactly five carrier files are created EXCL0400 outside the source: `source-current-observation-public.json`, `cohort.tar`, `export-inventory-public.json`, `cohort-manifest-public.json`, and `export-external-commitment-public.json`. Each has its first writer-FD eight fields and known SHA fixed after its final write/fsync; parent directories are fsynced. Only these new files receive their own three full9 stable observations over at least two seconds, within30 seconds, before any carrier FD9 is held. Their exact final rows are adopted and fenced; no post-admission ctime allowance exists. The independent commitment joins archive, manifest, inventory, new source-observation and original proof hashes. Neither the Root control nor any DB payload is copied into public JSON; DB bytes exist only in the intended raw public-fixture archive.

The final result is emitted only after source, external input and admitted-carrier fences pass. It is a terminal byte receipt, not a self-sealed historical FD9 claim. Failures independently attempt the existing input/source/admitted-output fences and preserve the first reason. There is no Docker, SSH, child process, DB API, C++ execution or signing in this exporter. All input/source paths are fixed; no dynamic file selection is accepted. Bounds remain128 MiB raw archive/payload,4096 entries/depth128 and180 seconds total, with30-second admissions. Candidate observation JSON is bounded to4 MiB each. A later cross-OS reader is a separate action.

The fixed fresh output is `qualification-resume-20261012/physical-native-export-root-20261018-01`.

Usage, after Root review/freeze only: `python3 runner.py CONTROL CONTROL_SHA256 CONTROL_BYTES RUNNER_SHA256 RUNNER_BYTES`. No invocation was made by the author. A success receipt reports source69/eight inventories, known pins, current source/carriers unchanged, Native04 whole failure preserved and old host results not requalified; C++ invocations, DB API opens, new signatures and image builds are all0, production false.

## Cross-OS gate remains separate

Root reports the Mac writer linked RocksDB11.8.1 and the retained Linux ARM reader closure RocksDB8.9.1. This package makes **no compatibility claim** between them. A future Root action must import the already validated archive into fresh Linux-native storage, keep its manifest hash independently, then check with an actual retained Linux reader in strict RO mode and verify CLI plus independent container exit, unchanged physical inventory and zero new signatures. A format/version rejection must remain a compatibility failure; no repair, migration, RW fallback or repeated producer is authorized by this proposal. An import is not operator restoration, old signing-history recovery, resumed duties, common finality, an independent security review, production readiness or Base–Nano/Doppler qualification.
