# Slots Capella : batch Merkle local et oracle public

Les cinq sources de ce lot passent le nouvel oracle public sur Docker Linux ARM64 et AMD64. La qualification porte sur les bytes épinglés, deux membres core remplacés dans l’archive 143 et les deux ELFs liés ; elle ne vaut pas qualification du nœud complet, des autres outils, de tout CMake/install ou de la production. La livraison Git se vérifie séparément.

Le batch garde localement les 28 racines de champs et deux arbres d’anneaux. Il conserve l’ordre racine pré-slot → state_roots → header → block_roots → epoch → slot ; l’epoch existante s’exécute sans raccourci et remplace le buffer, puis toutes les racines sont reconstruites. Entrées, marqueur, profil, limites et callback sont détenus avant le premier checkpoint ; limites d’allocation, annulations et erreur restent transactionnelles. La racine finale calculée localement doit égaler le hasher strict. Aucun header public/layout/ABI, format durable, cache global, réseau ou budget n’est modifié.

L’oracle indépendant n’utilise pas le nouveau batch pour construire ses états attendus. Il applique la récurrence manuelle stricte par slot et compare les bytes SSZ complets, processing metadata, racines et contextes target/registre/RANDAO/fork/duties/proposer/sync. Frontières epoch, historique, sync et eth1, deux tours d’anneaux, preset pur H72 non puissance de deux, refus et mutations du caller sont discriminés. Trois racines littérales issues de fixtures officielles épinglées et un état officiel post-slot vérifient les chemins stricts observé et non observé. Les sept fichiers publics sont inchangés dans le dépôt et leurs empreintes figurent dans le manifeste.

Plafonds inchangés : 180000 ms, 131072 KiB, 1024 signatures de test.

Le compteur couvre les vrais appels de paires du hasher BeaconState et du batch local ; il exclut les helpers epoch/execution inchangés. La référence stricte omet aussi ses hashes séparés du beacon header : son total est donc une borne inférieure conservatrice dans ce périmètre. La réduction comptée ne mesure ni CPU total ni accélération chronométrique ou privée. Les durées de deux architectures ne constituent pas un benchmark comparatif.

Les builds ont fait trois préflights/compilations (2 core + 1 test), deux liens, 141 membres conservés byte-exacts sur 143. L’objet CLI et son MD sont repris sans recompilation, puis reliés au nouvel ensemble. SDK, M/MD, source et artefacts protégés ont été vérifiés ; quatre vérifications SDK par exécution publique et containers possédés absents. Les anciens `--self-test` à 9 lignes/11 enfants CLI n’ont pas été rejoués. Le seul ajout CMake enregistre `consensus_capella_slot_merkle_batch_manual_oracle` dans la garde Linux existante ; le graphe CMake complet et l’installation ne sont pas qualifiés par ce build manuel. Tout autre outil doit garder sa propre cohérence objet/archive/MD avant un futur lien.

ARM est relu ici sur son log synthétique public, son terminal et l’agrégation ROOT. AMD est relu uniquement sur les résultats ROOT filtrés, sans lecture/export des logs, M/MD, ELF, inventaires ou empreintes bruts du VPS. Les statuts «tests non exécutés» des reçus de build décrivent leur instant de capture ; les reçus de test ultérieurs sont séparés.
