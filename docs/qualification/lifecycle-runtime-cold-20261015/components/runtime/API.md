# Lifecycle runtime integration contract

Source only. No campaign or program was executed by the author. The current unavailable guard remains until the new branch is complete and reviewed.

The actual driver consumes the new exporter deposit.json only. It binds public keys to the independently prepared owner inventory, polls the pinned immutable-state single-validator endpoint, waits real activation/tenure and finite profile-derived horizons, and uses the stopped C++ tool as the authority for every action and closing replay.

Each action follows clean stop, two independent P/W captures, new private physical core copies, sealed observe, eligibility-checked prepare, known PREPARED action SHA/bytes, and a NEW submission plan. Its SHA is calculated from known bytes before O_EXCL/fsync, admitted once after bounded first stability, then passed unchanged to the managed lifecycleSubmit child. The driver never reads a supervisor token, retries an uncertain Submit, or manufactures an accepted Job.

The private VPS transfer gate defaults false and refuses before seed/ledger/export/network. Cross-owner evidence also defaults false and requires specific external human approval represented by the ROOT-approved SPEC. No per-phase manual approval channel is introduced. Owner-local action/job/capture artifacts remain owner-local; only expressly approved local-to-VPS evidence is transferred. Full terminal replay runs once on VPS in situ; three stopped owner captures are separate evidence.

First restore is after activation and a finalized proposal by the new validator, before either action. The second restore is after both finalized full payout candidates and uses a third currently active local identity for resumed duties. Two source/restored capture artifacts, signed proposal roots before/after each restore, exact finalized action roots and fresh deposit raw/hash bind the C++ closing evidence. Canonical replay is mandatory to qualify exact debits, total recipient credits, penalties/rewards and increasing withdrawal indices. Finalized public withdrawal entries schedule the second restart; a permanently zero post-state balance is neither required nor used as the payout oracle.

Existing ordinary recovery/partition flows must retain their prior behavior. The candidate adds lifecycleTool and lifecycleSubmit roles to each owner admission and keeps the same profile/clocks/images. Every long wait and child remains bounded by the declared whole-run horizon and phase deadline.

Long waits refresh the baseline only through the inherited authenticated three-owner common-finality observer. The profile/deadline-derived window reserves three epoch advances and the full observer timeout under its existing 1,024 ancestry bound. A missed window refuses. Head/state headers are triggers and immutable validator selectors, never replacement finality authority. Terminal checkpoint epochs are normalized from observer decimal strings to C++ canonical hex quantities.
