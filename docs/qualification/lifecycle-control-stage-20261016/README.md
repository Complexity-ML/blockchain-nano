# Transport des contrôles lifecycle et preuves d'arrêt

Le transfert initial du mode lifecycle fournit désormais les cinq fichiers publics du manifeste, dont `genesis-state.ssz` et `genesis-validators.ssz`. Leurs noms, tailles et SHA sont vérifiés sur les buffers effectivement archivés avant le démarrage des nœuds. Huit fichiers de configuration sont transportés dans ce mode ; le mode ordinaire reste à six. Le nombre de clés privées VPS reste 33, sans ajout ni transfert nouveau.

Un reçu d'arrêt réussi est conservé pour son propriétaire et ses racines/montages exacts. Toute tentative de reprise l'invalide avant la première opération asynchrone ; une dérive des racines est refusée. La clôture peut ainsi capturer les trois propriétaires même si l'un était déjà arrêté avant une erreur de préparation. Chaque capture publie aussi immédiatement son engagement public durable avant l'étape suivante. Les capsules et journaux privés restent sur leur hôte. La publication des trois captures précède toujours l'audit final, dont un échec reste un échec.

Les 52 projections Linux et les 63 entrées hôte contrôlées restent inchangées. Le scénario causal sur l'ancien module refuse huit fichiers à sa limite de six ; le candidat fournit toutes les feuilles attendues avec leurs octets et pins. Aucun runtime, réservation de domaine, clé, signature, base réelle, compilation C++ ou build d'image.
