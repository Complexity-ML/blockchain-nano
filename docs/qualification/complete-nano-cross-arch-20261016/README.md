# Nano lié et vérifié par CLI dans trois environnements (deux architectures CPU)

ROOT a lié un binaire Nano complet aux Core courants sur Mac natif, Docker ARM et Docker AMD64 du VPS. La base C++ est le commit `2443a5c058c75361349daaf66645b62f489c2e6f`, avec le seul overlay du test `3f3dc2bc…/12665`. Chaque binaire passe deux smokes ciblés : `--help` sort avec 0 ; l’arité RPC incomplète sort avec le code 1 attendu. Ces commandes précèdent l’ouverture de DB, le réseau et les duties. Les archives et exécutables sont identifiés dans les reçus ; aucun runtime de nœud n’est démarré.

Sur Native, le Main est recompilé car son ancienne identité neuf-champs n’était pas retenue dans l’autorité sélectionnée. Le nouveau membre RPC égale l’objet compilé ; les 142 autres membres restent inchangés sur 143. Les dépendances Main/RPC/test sont respectivement 1 218/1 266/1 205, avec 1 350 matériaux tenus et 1 225 gardes d’alias sélectionnées. Ces mesures ne qualifient pas le SDK global. La baseline ancien Core est refusée exactement au stage `canonical-selectors`, avec `checks:4` et le code 1 attendu ; le candidat RPC passe. Les stdout RPC natifs sont byte-identiques aux preuves Linux antérieures, sans les rejouer.

Le test adapté `3f3dc2bc…/12665` détecte l’API RocksDB par template : sortie `unique_ptr` ou repli DB**. Il est qualifié sur Native uniquement. Les preuves RPC Linux conservent le fichier antérieur `73b86060…/12238` ; aucune compilation ou nouvelle branche du test adapté n’est qualifiée sur Linux. Les assertions et compteurs ne changent pas. Le test est l’unique modification projet de ce lot ; src/include/third_party et CMake restent inchangés.

Pour ARM, le tail de lien vient de l’ordre canonique retenu d’un autre consommateur de nano_core, associé aux deux déclarations Nano du CMake courant. Il ne provient pas d’une ancienne recette Nano ARM récupérée et ne constitue pas un configure CMake complet. Les deux Linux réemploient leurs Core RPC déjà qualifiés : aucun membre n’est recompilé ou requalifié par le worker de reliaison. Sur AMD, 93 empreintes projet du producteur Main sont rapprochées des sources retenues. Les anciens SDK complets ne sont pas réaudités ; les dépendances sélectionnées de l’image restent distinctes de ces anciennes autorités.

Deux échecs sont conservés. Native01 compile Main, puis le test échoue réellement sur l’API RocksDB 11 (DB** remplacé par une sortie unique_ptr) avant tout test RPC. ARM01 refuse avant initialisation : une boucle de contrôles avait remplacé le nom du conteneur. Zéro M/CXX/programme projet y est exécuté ; seul le volume neuf vide est supprimé après vérification de son label et de son absence d’utilisation. Les fences des anciens matériaux passent dans les deux cas ; aucun refus n’est transformé en réussite.

Après succès, les conteneurs Linux possédés sont absents ; le volume ARM et le répertoire AMD restent conservés. Les fences finales gardent 18 fichiers hôte pour ARM, 20 pour AMD, et les matériaux/alias sélectionnés Native inchangés. Le readback AMD retrouve le même reçu public et les mêmes engagements Nano/admission avec source propre, sans table privée retournée. Les digests d’admission publiés n’admettent pas les 24 rôles dans une campagne.

Les neuf reçus publics, le worker partagé et le patch du test sont copiés exactement. Les six contrôleurs réellement exécutés et les manifestes source figés sont référencés par SHA/taille dans le manifeste, sans duplication ; les résultats sont portés par les reçus. Le test R déjà présent en 3f3 doit être validé sans réécriture de ses mêmes octets. Les préfixes des quatre documents sont fournis séparément de leurs corps historiques, conservés intégralement comme suffixes. Aucun SDK brut, clé, table privée, binaire ou log opérationnel n’est inclus.

Ce lot ne qualifie pas CMake global, le loader complet et ses symboles lazy, le SDK/DAG complet, le nouveau test adapté sur Linux ou HTTP ; il conserve les qualifications historiques dans leurs portées acquises. Les 24 admissions, la reprise du runtime réseau, la restauration des journaux, les duties, la finalité commune, le déploiement et la production restent ouverts. La portée EIP-1898 demeure partielle pour eth_call ; estimateGas est une extension Nano. L’échec global historique hors closure et toutes les limites antérieures restent conservés. Le goal demeure actif.
