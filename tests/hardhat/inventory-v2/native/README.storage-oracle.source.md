# Independent secure-storage MPT diagnostic — SOURCE ONLY

This is one offline JavaScript calculator/verifier using **ethers6.16.0 RLP and Keccak primitives**, with its own trie/path algorithm and no Nano/Core/RLP implementation import. The author read only the explicitly designated public paired-account JSON for its schema; no dataset calculation, Node/test/client/Docker/SSH/Git/private-input operation was executed. Original execution results, strict root mismatches, inputs and Core remain unchanged.

```text
node storage-oracle.mjs PAIRED_JSON INPUT_SHA NODE_MODULES ANVIL_STATE_ROOT NEW_OUTPUT
```

Root supplies/pins the existing public JSON bytes, ethers tree and **Anvil block3 stateRoot from its separately retained trace**. The stateRoot must not be learned from the proof under verification or confused with Native's divergent root. Input/output/module paths must be absolute and output must be new. One bounded readonly input FD is SHA/length/full-nine/path fenced and closed; output is exclusive0600 and fsynced/closed. The offline budget is60seconds and no client is launched. The external terminal/elapsed/dependency/input authority remains Root's responsibility.

The pure exports build secure storage tries from each Native map: uint256 slot keys padded to32bytes then Keccak-hashed; zero values omitted; nonzero values encoded as canonical minimal integer RLP; hex-prefix leaf/extension paths;16-way branches; nested inline child lists only below32encoded bytes, otherwise hashed references. Root nodes are always hashed. Each account exposes its independent root, root-node RLP and constructed node records for comparison with Native's reported root and the authenticated reference storageHash. There is no canonicality exception, synthetic zero leaf, adaptive state edit or forced-root normalization. Counts come from each map rather than a hardcoded interpretation of '15slots'.

Before trusting a reference storageHash, the verifier follows that account's secure-address `accountProof` from the **external Anvil stateRoot**, verifies referenced node hashes and canonical RLP, and checks the exact nonce/balance/storageHash/codeHash account payload. Nonmembership must report empty account fields. It then verifies each requested secure-slot proof from that storageHash: hash/inline references, bounded noncyclic path traversal, compact flags/padding, branch absence or exact leaf membership and canonical RLP integer value. Proof value and separately retained direct slot read must equal the authenticated leaf. The original JSON `.matches` booleans are never authority. Duplicate/unconsumed proof nodes, missing references, malformed paths, wrong roots or substituted leaves refuse the calculation; an invalid reference proof must not be attributed to Core.

Limits are14unique paired addresses,1024map entries/account,128nodes and1MiB/node-list per proof,128traversal steps and16MiB input/output. Code bytes must hash to the reported code hashes. Requested proof/direct-read sets must bind every Native key exactly. The output records whether authenticated reference values equal Native values and whether the independently reconstructed root matches Native, reference, both or neither. If it equals the authenticated reference root, the known map has that same cryptographic commitment (assuming Keccak collision resistance); no reference enumeration is claimed. If only Native matches while selected reference values match too, additional/unseen reference entries remain possible. The tool must not infer a storage cause merely from14matching account summaries.

All output says `passed:false` and `productionQualified:false`; `analysisCompleted:true` means the offline checks completed. Account/storage proof verification is relative to the externally retained private-reference root, **not consensus/finality authentication**. Root must adopt only after actual exit0, closure and budget checks; files alone are not a terminal success. This calculator neither fixes nor suppresses the original stateRoot mismatch, qualifies the full EVM, activates a fork, backs real assets or makes the L1 production-ready.
